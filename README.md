# Yaeri / Яэри 🦊

Персональная восьмихвостая лисица — AI-помощница. Отвечает через модели **Cloud.ru Foundation Models**, хранит историю и долговременную память в локальной базе и умеет искать ответы в ваших документах (RAG).

## Запуск в Windows

1. Скачайте весь репозиторий через **Code → Download ZIP** и распакуйте его (или выполните `git clone`).
2. Дважды нажмите **`Yaeri.bat`**.
3. Сайт автоматически откроется в браузере по адресу вида **`http://127.0.0.1:49231/`**. Число порта выбирает сама Windows; оно будет другим при каждом запуске.
4. Для остановки закройте окно запуска или нажмите **Ctrl+C**.

**Python, Node.js и установка пакетов не требуются.** Нужна Windows 10/11 со встроенным Windows PowerShell 5.1 и браузером.

### Что предусмотрено

- Русский интерфейс и русские сообщения в окне запуска.
- Пути с пробелами и кириллицей: например, `C:\Пользователи\Мои проекты\Яэри`.
- Корректное использование кавычек в BAT-файле.
- Автоматический свободный порт (TCP 0) без ручной настройки.
- Адрес **127.0.0.1**: сайт доступен только на этом компьютере, не в локальной сети и не в интернете.
- Автоматическое открытие браузера. Если открыть браузер не удалось, адрес отображается в окне.
- Без ключа Cloud.ru работает демо-режим: сообщения хранятся в браузере (localStorage).
- Логотип проекта (`site/logo.svg`): лисица с восемью хвостами. При открытии страницы хвосты раскрываются веером.
- Настройки проекта: шестерёнка в правом верхнем углу открывает панель. В ней можно задать обращение, цвет оформления, размер текста, анимации, отправку по Enter и показ времени. Настройки хранятся в браузере.

### Если сайт не открылся

- Не закрывайте окно, которое открыл `Yaeri.bat`: в нём работает сервер.
- Скопируйте точный **«Адрес сайта»** из окна и откройте в браузере.
- Проверьте, что скачали **всю папку**, включая `launcher/start.ps1` и `site/index.html`.
- Если PowerShell заблокирован политикой организации, обратитесь к администратору. BAT использует `-ExecutionPolicy Bypass` только для запущенного процесса и не меняет политику компьютера.
- Если первый запуск прошёл, а вкладка закрыта, можно снова открыть адрес из окна BAT.

## Подключение Cloud.ru

1. Получите API-ключ в личном кабинете Cloud.ru (сервис Foundation Models).
2. Запустите `Yaeri.bat`. Без ключа сайт откроется в демо-режиме.
3. Откройте **⚙ Настройки → Подключение Cloud.ru** (или нажмите «Подключить Cloud.ru» под чатом), вставьте ключ и нажмите «Сохранить и подключить». Яэри сразу проверит ключ запросом к Cloud.ru и перейдёт в онлайн, перезапуск не нужен.
4. Ключ сохраняется в `config\yaeri.config.json`. Этот файл в `.gitignore`: он не попадёт в git. Обратно в браузер ключ не отдаётся — страница видит только «ключ задан», а все запросы к Cloud.ru идут через локальный сервер. Там же можно проверить связь, заменить или удалить ключ.

Если в настройках написано «Сервер Яэри не ответил на проверку: Запрос отклонён…», страница открыта не с локального сервера Яэри (другая вкладка, закладка от прошлого запуска или чужой адрес). Откройте адрес, который показан в окне `Yaeri.bat`. Причина отказа и полученные заголовки `Host`/`Origin` печатаются в этом окне жёлтым.

Вместо ввода можно скопировать `config\yaeri.config.example.json` в `config\yaeri.config.json` и вписать ключ в поле `apiKey`, либо задать переменную окружения `CLOUDRU_API_KEY`.

### Выбор модели

Модель выбирается в **⚙ Настройки → Подключение Cloud.ru**: список подгружается из Cloud.ru (`/v1/models`), выбор сохраняется в `chatModel` в `config\yaeri.config.json`. Текущая модель видна в шапке чата, клик по ней открывает настройки. Модель по умолчанию и прочие параметры задаются в `config\yaeri.config.json`:

| Поле | Значение |
|---|---|
| `chatModel` | модель по умолчанию для ответов |
| `chatModels` | дополнительные модели для списка, если Cloud.ru не отдал перечень |
| `embeddingModel` | модель эмбеддингов для RAG и памяти |
| `temperature`, `maxTokens` | параметры генерации |
| `historyTurns` | сколько последних реплик отправлять модели |
| `ragTopK`, `memoryTopK`, `minScore` | сколько фрагментов документов и памяти подмешивать и минимальная близость |
| `systemPrompt` | свой системный промпт; `{name}` заменяется обращением |

После правки файла перезапустите Яэри.

## Командный центр и рабочая память

Сайт открывается на **командном центре** — тёмной панели в стиле HUD:

- **Рабочая память** (слева) — короткие факты по разделам: Задачи, Планы, Профиль, Люди, Проекты, Предпочтения или свои. Заметки можно добавлять, закреплять (★) и удалять. Яэри видит их в **каждом** ответе: они уходят в системный промпт (закреплённые первыми, до ~6000 символов).
- **Яэри сама ведёт рабочую память**: если в разговоре прозвучал устойчивый факт («в субботу еду в Казань»), модель ставит в конце ответа скрытый тег `<память раздел="Планы">…</память>`. Сервер забирает факт в память и убирает тег из текста, а под ответом видно «✦ Записала в память». Выключается в настройках («Яэри ведёт рабочую память»).
- **Разговор** (в центре) — чат с Яэри. Слева от переписки стоит сама Яэри, и её поза показывает, что происходит (см. «Аватар» ниже).
- **Сейчас** — часы и календарь месяца, точками отмечены дни с новыми заметками и разговорами.
- **Второй мозг** (мини-карта), **Навыки** — быстрые команды с кнопкой ▶ (`/план-дня`, `/что-помнишь`, `/итоги`, `/идеи`, можно добавить свои), **Журнал** — последние события памяти.

### Аватар

Яэри нарисована в восьми позах (`site/yaeri/*.webp`, фон вырезан, у каждой позы есть крупный план лица `*-face.webp`). В «Командном центре» большой фигуры в чате больше нет: чат занимает всю ширину, а в шапке чата и на круглой кнопке в углу показывается лицо, которое меняется вместе с позой (полноростовые картинки поз в интерфейсе не используются). Поза меняется сама:

| Поза | Когда |
|---|---|
| сидит | ждёт, «слушаю вас» |
| поправляет волосы | вы печатаете сообщение |
| лисий огонь в руке | думает над ответом |
| танцует | ответила или записала в память |
| кланяется с улыбкой | приветствие |
| прикрывает рот | смеётся, если нажать на неё |
| глаза закрыты | дремлет после трёх минут тишины, просыпается от любого действия |
| глубокий поклон | извиняется, если ответ не получился |

Клик по лицу Яэри в шапке чата ставит курсор в поле ввода. Во «Втором мозге» и когда чат прокручен за экран, в правом нижнем углу появляется круглый аватар: нажмите — и чат откроется поверх страницы (Esc или × сворачивает).

### Второй мозг

Вкладка **«Второй мозг»** (или адрес `#brain`) показывает всё, что знает Яэри, как граф: в центре ядро «Яэри», вокруг — группы и узлы (● заметки, • воспоминания о разговорах, ■ документы). Линии между воспоминаниями и документами — **связи по смыслу**, посчитанные по эмбеддингам.

- Раскладки: **Кольца**, **Созвездие**, **Соты**, **Силы**, **Время** (лента по датам).
- В «Кольцах» разделы памяти — плотные клинья точек вокруг ядра, разговоры — внешнее кольцо кружков-иконок по месяцам; кольца медленно вращаются (ползунок «Вращение колец», при наведении замирают).
- Клик по разделу подсвечивает веер связей ко всем его узлам и открывает карточку раздела. Подсказка показывает размер и давность («3 дня назад»).
- «Показ на весь экран» — только граф, без панелей, кольца вращаются; выход — Esc.
- Группировка: по разделам или по типам.
- Ползунки вращения колец, силы пружин (для «Сил»), яркости связей, размера узлов и подписей; названия узлов при приближении.
- Поиск по памяти (клавиша `/`, Enter — перелёт к найденному).
- Клик по узлу открывает карточку: закрепить, изменить, удалить, «спросить Яэри»; раздел сворачивается кнопкой в его карточке.
- Колесо мыши — масштаб, перетаскивание — сдвиг; «Развернуть всё», «Свернуть всё», «В центр».
- Темы: Яэри (цвет сайта), Металлик, Рубин, Океан, Неон, Бордо, Бумага. «Сохранить вид» запоминает настройки графа в браузере, «Скачать PNG» сохраняет картинку.

В демо-режиме рабочая память хранится в браузере, а во втором мозге видны заметки и локальная переписка.

## Душа Яэри

У Яэри есть душа — внутреннее состояние, которое растёт от разговора к разговору. Она видна в разделе **Душа** (вкладка сверху) и в маленькой карточке «Душа» в командном центре.

- **Девять хвостов души.** Каждая реплика даёт 1 опыт, каждое раздумье — 5. С опытом зажигаются хвосты и меняется ступень: Искорка → Пробуждение → Любопытство → Знакомство → Доверие → Понимание → Привязанность → Родство → Девятый хвост.
- **Характер** — тепло, любопытство, игривость, забота, мудрость, смелость (0–100). Меняется медленно, не больше чем на 3 за раз.
- **Настроение и близость с вами** — что она сейчас чувствует и почему.
- **Как она видит вас** — портрет хозяина, его цели, что нравится, что тревожит.
- **Что она поняла** — уроки о том, как лучше с вами говорить.
- **Дневник** — записи от первого лица после каждого раздумья.

Как она растёт: после 6 обменов репликами и паузы в ~45 секунд Яэри «думает» — отдельный запрос к модели перечитывает разговор и возвращает небольшие изменения души. Когда вы приходите снова, она обдумывает прошлый разговор, а если вас не было больше 6 часов, просто думает о вас. Мысль, которой ей хочется поделиться, она пишет в чат первой (с пометкой «думала о вас»). Душа добавляется в системный промпт и мягко окрашивает тон ответов.

Как душа растёт дальше:

- **Важные моменты** — ваши успехи, решения, первые разы. Что вспоминается в разговорах, крепнет; что нет, со временем бледнеет и забывается. Моменты с 📌 не забываются.
- **«Сон»** — раз в сутки, когда вы минут 15 не трогаете Яэри (или при запуске, если компьютер был выключен больше полутора суток), она засыпает: память бледнеет, похожие моменты объединяются, повторы в представлении о вас и в уроках убираются, а в дневнике появляется сон и новое понимание. Можно усыпить кнопкой «Уснуть сейчас».
- **Умения за хвосты**: /стих (2), /совет (3), /бережный-день (4), /сказка (5), /зеркало (6), /мечта (7), /письмо (8), /наш-путь (9). Открытые умения появляются в «Навыках» командного центра.
- **Её мир**: собственные увлечения, которые растут из разговоров; свои мнения и вкусы, с которыми она может мягко не согласиться с вами; личные цели с прогрессом (можно подарить ей цель).
- **Ваше настроение по дням** — полоска за 30 дней. Если вам грустно 2 дня подряд и больше, Яэри становится особенно бережной.
- **Утром и вечером** она пишет первой: пожелание на день и вопрос «как прошёл день?», раз в день каждое (выключается в настройках).

Как она думает:

- **Внутренний монолог.** Перед ответом Яэри коротко думает про себя: что вы чувствуете, что она о вас помнит, что подсказывает душа. Мысли можно развернуть под ответом («мысли Яэри»).
- **Самопроверка.** Быстрая модель перечитывает ответ и исправляет его, если он противоречит рабочей памяти или тому, что Яэри знает о вас. Под исправленным ответом стоит «перечитала и поправила себя».
- **Две модели.** В **Настройки → Подключение** можно выбрать «умную» модель. Ею Яэри отвечает на сложные вопросы (анализ, код, планы, расчёты, длинные тексты), думает о разговорах и спит; болтовня идёт на основной модели.
- **Поиск по смыслу в своих воспоминаниях.** Важные моменты и записи дневника получают эмбеддинги Cloud.ru (`data\soul-vectors.json`). Перед ответом Яэри находит близкие по смыслу и «вспоминает» их; вспомнившийся момент крепнет.
- **Потребности**: скучает (растёт, пока вас нет), радость и любопытство. Они меняют её поведение: соскучившись, она рада вас видеть; любопытная — задаёт вопрос о вас.
- **Сны.** То, что приснилось во время «сна», она рассказывает вам утром.
- **Секреты.** С ростом близости (20, 35, 50, 65, 80, 95) Яэри открывает секреты о себе и маленькие подарки. Открыть их можно в разделе «Душа».

Что видно:

- **Душа во «Втором мозге»**: важные моменты, её увлечения, мнения, цели и сны — розовые ромбы в своих группах «Душа · …».
- **Живая подсветка**: после ответа на графе (и в мини-графе командного центра) несколько секунд светятся воспоминания, документы и моменты, на которые Яэри опиралась.
- **Как менялся характер**: график черт по дням (точка записывается после каждого раздумья и ручной правки).
- **Дневник с поиском и календарём**: поиск по тексту и настроению, дни с записями отмечены в календаре, клик по дню показывает только его записи.

Всё можно поправить руками: текст «кем она себя чувствует», портрет, списки, черты характера (ползунки), уроки, записи дневника. Кнопка «Подумать сейчас» запускает раздумье сразу, «Сбросить душу» начинает всё заново (переписка и память остаются). Выключить рост можно в **Настройки → Память и знания → Душа Яэри растёт**.

## База данных и RAG

Всё хранится локально в папке `data\` (в `.gitignore`), в виде JSON-файлов — без установки SQLite или других программ:

- `history.json` — переписка;
- `memory.json` — долговременная память: каждая пара «вопрос — ответ» с эмбеддингом;
- `docs.json` — загруженные документы, нарезанные на фрагменты, с эмбеддингами;
- `notes.json` — рабочая память: заметки по разделам (без эмбеддингов, до 1000 штук);
- `soul.json` — душа Яэри: характер, настроение, представление о вас, уроки и дневник.

Как работает ответ: вопрос превращается в эмбеддинг (Cloud.ru), локальный сервер находит самые близкие фрагменты документов и прошлых разговоров (косинусная близость), добавляет их в системный промпт и отправляет модели вместе с последними репликами. Под ответом видно, какая модель отвечала и какие источники использованы.

Документы добавляются в **Настройки → Документы для RAG**. Поддерживаются текстовые файлы (`.txt`, `.md`, `.csv`, `.json`, `.html` и т. п.) до 1 000 000 символов; PDF и Word пока нужно сохранить как текст. Если сменить `embeddingModel`, появится кнопка «Переиндексировать».

В настройках также можно выключить RAG или запоминание и стереть память. «Очистить чат» удаляет переписку, но не память.

Резервная копия — просто скопируйте папку `data`.

## Статус

Работает AI-чат через Cloud.ru с выбором модели, рабочей памятью, «вторым мозгом», долговременной памятью и RAG по документам. Есть аватар Яэри с позами по настроению и душа, которая растёт и думает о хозяине. Голос будет добавляться отдельно.

Примечание: запуск требует Windows PowerShell 5.1; на macOS и Linux этот `.bat` не работает.


## Soul Evolution — автономная память и развитие

Поверх существующей «Души» добавлен механизм автономного развития. В разделе **Душа → Автономная жизнь** видны очередь обучения, последние события, история изменения характера и мнений и знания с оценкой уверенности.

- **Фоновый планировщик** живёт в `launcher/start.ps1`: раз в минуту проверяет, нужна ли задача, но выполняет не более одной фоновой задачи за цикл. Он работает **без открытой вкладки**, если окно сервера `Yaeri.bat` остаётся запущенным. Когда Windows выключена или сервер остановлен, вычислений нет; при следующем запуске просроченные операции обнаруживаются по сохранённым временным меткам.
- **Самостоятельные размышления** используют текущий `Invoke-YSoulReflect`, а «сон» — `Invoke-YSoulSleep`. Обновления характера фиксируются в журнале изменений с причиной.
- **Обучение на опыте** извлекает полезные факты, эпизоды и явные исправления из очереди разговоров. Для каждой записи требуется дословная цитата исходного **сообщения пользователя**. Слова модели не считаются доказательством пользовательских фактов.
- **Семантическая память** хранит свойства с уверенностью, хронологию эпизодов, исправления и близкие по эмбеддингам ассоциации. Противоречащие сведения не перезаписывают подтверждённые факты без достаточной уверенности; старые версии помечаются как заменённые.
- **Избирательное забывание** постепенно ослабляет малозначимые эпизоды и архивирует их, а подтверждённые факты не удаляет автоматически. Вероятно устаревшие планы и статусы помечаются для уточнения.
- **Мнения Яэри** могут меняться на основе полученного опыта; предыдущая формулировка и причина изменения остаются в истории.
- **Отключение и удаление**: переключатель «Фоновое обучение и память» приостанавливает фоновые задачи и запись новой автономной памяти; кнопка «Очистить автономную память» удаляет факты, эпизоды, ассоциации, исправления, события и историю перемен из нового хранилища. Старые `history.json`, `memory.json`, `notes.json` и `soul.json` управляются отдельно.

Данные автономной жизни сохраняются в `data/soul-evolution.json`, который автоматически исключён из git вместе с папкой `data/`. Дополнительный PowerShell-модуль: `launcher/yaeri-evolution.ps1`. API: `GET /api/soul/evolution` для просмотра, `POST /api/soul/evolution` для переключения и `POST /api/soul/evolution/clear` для очистки.

**Ограничения:** сервер обрабатывает запросы последовательно, поэтому длительное фоновое обращение к Cloud.ru может временно задерживать чат. Между платными фоновыми задачами выдерживается минимум 10 минут; после ошибки — пауза не менее 30 минут. Данные извлекаются эвристически с помощью модели, поэтому оценки уверенности не являются гарантией истинности. Автозапуск Windows и отдельная служба пока не добавлены.

Для проверки на Windows запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\\test-soul-evolution.ps1`. Также есть `node tests\\check-site.js` и GitHub Actions workflow для Windows PowerShell 5.1.

## Yaeri Soul 3.0 — разум, характер и заботливые отношения

Soul 3.0 — дополнительный локальный слой поверх «Души» и Soul Evolution. Четыре модуля Windows PowerShell 5.1:

- `launcher/yaeri-growth.ps1`: устойчивые ценности, память взросления, интересы, переломные моменты, настройка стиля близости и журнал роста.
- `launcher/yaeri-reason.ps1`: причинно-следственные утверждения с дословным подтверждением, контекст неопределённости, проверка исправлений и планы с подтверждаемыми шагами.
- `launcher/yaeri-bond.ps1`: память о значимых разговорах, предпочтения нежного общения, примирение после ошибок и ненавязчивые инициативы.
- `launcher/yaeri-relationship.ps1`: договорённости, сроки, проверка исполнения и извлечение подтверждённых отношений из разговоров.

Данные — `data/soul3.json` (игнорируется Git). Прежние файлы `soul.json`, `soul-evolution.json` и история остаются нетронутыми. **Раздел «Душа → Разум, близость и развитие»** показывает ценности, историю, знания о предпочтениях, планы и договорённости; позволяет включить/выключить Soul 3.0, выбрать дружеский, нежный или романтический стиль (это стиль вымышленного AI-персонажа, а не реальные чувства), включить инициативу по желанию и удалить отдельные данные Soul 3.0.

Память об отношениях извлекается в рамках уже существующего фонового обучения Soul Evolution (не требуется дополнительный вызов модели): каждое утверждение обязано иметь дословную цитату сообщения пользователя. Исправления и причинно-следственные связи отличаются от доказанных независимыми источниками фактов. После подтверждённых важных событий или выполненных обещаний показатель доверия может расти, но не растёт просто от количества сообщений. Без разрешения пользователя нежные инициативные сообщения не генерируются.

Планы создаются **по запросу пользователя**: AI формирует шаги, но не исполняет внешние действия автоматически. Обещания добавляются явно пользователем, завершение отмечается вручную. Просроченная договорённость может появиться как ненавязчивая внутренняя мысль, только если инициативы включены. Ни романтический стиль, ни преданность не означают слепого повиновения, контроля или ревности. Яэри не должна утверждать, что совершила действие, если у неё нет подтверждения.

Новый API: `GET /api/soul3`, `POST /api/soul3/settings`, `POST /api/soul3/clear`, `POST /api/soul3/plans`, `POST /api/soul3/plans/step`, `POST /api/soul3/promises`, `POST /api/soul3/promises/update`. Все запросы обрабатываются локально, с теми же проверками Host/Origin, что и остальные endpoints.

**Фоновый режим** требует, чтобы локальный сервер `Yaeri.bat` был запущен; открытая вкладка не обязательна. Без сервера или при выключенном компьютере фоновых вычислений нет. Задания и данные возобновляются при следующем старте. Cloud.ru требуется для извлечения воспоминаний и AI-планирования; ручные планы, настройки и обещания хранятся локально. Длинные запросы по-прежнему могут временно задерживать однопоточный HTTP-сервер.

Проверки: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\\test-soul3.ps1`, `node tests\\check-site.js` и CI на `windows-latest`.

## Самообучение и рост: фоновое любопытство, уроки и учебные цели

Модуль `launcher/yaeri-curiosity.ps1` делает так, чтобы Яэри росла и без разговоров. Планировщик (раз в минуту в том же потоке сервера) выбирает по приоритетам: разговоры хозяина, уроки на ошибках, порядок в памяти, мнения, сон, раздумья, затем собственные учебные цели и любопытство.

- **Любопытство.** Пока вас нет (20+ минут), Яэри задаёт себе до двух новых вопросов о вас и ищет ответы в своей памяти и в ваших документах (RAG). Ответ сохраняется как **гипотеза** («не факт»), никогда не попадает в проверенные знания сам и в разговоре подаётся с оговоркой, пока вы не нажали «Это так». Без ответа вопрос остаётся открытым, и она может бережно спросить вас сама.
- **Уроки на ошибках.** Каждая ваша поправка превращается в короткое правило, которое подмешивается в её промпт («Уроки на твоих ошибках»).
- **Учебные цели.** У Яэри есть до двух своих целей роста с шагами. Прогресс честный: без новой практики за раз растёт не больше чем на 3%, с практикой не больше чем на 12%. Достигнутая цель даёт опыт и двигает ступени хвостов.
- **Очередь приоритетов и пауза при сбоях.** Вместо одного жёсткого интервала шаг зависит от выбранной активности: «Выкл» (только разговоры, сон и раздумья), «Тихо», «Обычно», «Активно». При сбоях пауза растёт: 5, 10, 20, 40, не больше 60 минут.
- **Лимит запросов.** Любой фоновый шаг расходует запросы к Cloud.ru. Дневной лимит (по умолчанию 60, можно 30/150/300 или без лимита) останавливает фоновую учёбу до полуночи. Кнопка «Учиться сейчас» обходит паузу и лимит.
- **Видимость роста.** Вкладка «Душа → Рост»: лесенка из девяти ступеней с датами, графики опыта, знаний (знания, эпизоды, догадки, уроки), фоновых запросов по дням, радар характера «было/стало», учебные цели с шагами, догадки с подтверждением, уроки и лента «Что нового». Данные — `data/soul-curiosity.json` (игнорируется Git).

Вкладка «Душа» разбита на разделы **Сейчас · Рост · Память · Мир · Характер**; наверху герой-блок с позой и аурой по настроению.

API: `GET /api/soul/growth`, `POST /api/soul/growth/settings` (`intensity`: `off|quiet|normal|active`, `dailyLimit`), `POST /api/soul/growth/insight` (`id`, `action`: `confirm|dismiss`), `POST /api/soul/growth/run`, `POST /api/soul/growth/clear`.

Проверки: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test-soul-curiosity.ps1` (модель в тесте подменена, сеть не нужна) и `node tests\check-site.js`.

## Понимание хозяина: карта, состояние, вопросы, оценки и память по темам

Модуль `launcher/yaeri-understanding.ps1` (данные — `data/soul-understanding.json`, игнорируется Git).

- **Карта человека.** Раздел «Мир → Карта человека»: люди рядом, проекты, распорядок, привычки, места, что помогает и что выматывает. Записи извлекаются **из того же запроса**, что и обычное изучение разговора (отдельных платных запросов нет), и принимаются только с дословной цитатой хозяина. Любую запись можно удалить или добавить вручную.
- **Чтение состояния.** По каждому сообщению локально (без модели) определяется: устали, торопитесь, на нервах, грустите, в хорошем настроении. Это грубая оценка; в промпт попадает только при достаточной уверенности и подстраивает длину и тон ответа. Видно в «Сейчас → Как она вас читает».
- **Вопросы по пробелам.** Для пустых разделов карты в промпт добавляется один мягкий вопрос: не чаще раза в 3 часа, об одном разделе не чаще раза в сутки и никогда, когда вы устали, торопитесь, на нервах или грустите. Любой раздел можно отключить («Не спрашивать») или попросить спросить сразу.
- **Оценки ответов.** Под ответами Яэри в чате кнопки 👍/👎 (для 👎 можно написать, что не так). Плохие оценки планировщик сам разбирает в урок-правило (даже при активности «Выкл», не чаще раза в 5 минут). Статистика и графики — «Рост → Качество ответов».
- **Память по темам.** Темы: здоровье, деньги, семья, отношения, работа, учёба, творчество, быт; режимы **«Открыто»**, **«Не использовать без запроса»** и **«Не запоминать»**. Здоровье и деньги по умолчанию «Не использовать без запроса»: такие записи хранятся, но не попадают в промпт и в догадки Яэри, пока вы сами не упомянете тему в этой реплике. «Не запоминать» блокирует запись новых знаний, эпизодов, заметок и карты по теме. Темы определяются по ключевым словам, поэтому это грубый фильтр, а не гарантия: нестандартные формулировки он не поймает. Уже записанное в других местах (дневник, моменты) фильтруется по тому же принципу при показе модели, но не удаляется.

API: `GET /api/soul/understanding`, `POST /api/soul/understanding/map` (`action`: `add|delete`), `/topic` (`topic`, `mode`: `open|hold|off`), `/gap` (`section`, `action`: `ask|dismiss|restore`), `/clear`, а также `POST /api/soul/rate` (`id`, `score`: `1|-1|0`, `note`).

Проверки: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test-soul-understanding.ps1`.

## Глубина души: предчувствие, варианты будущего, свой характер, философия, навыки и самоулучшение

Вкладка «Душа» → «Глубина». Модуль `launcher/yaeri-depth.ps1`, данные в `data\soul-depth.json`.

- **Предчувствие.** По ритму сообщений (ночные сессии, длинные сессии без перерыва, усталый или напряжённый тон, одна и та же тема с «не получается» несколько дней) Яэри замечает выгорание или застревание и один раз мягко предлагает передышку или другой подход. Считается локально, без запросов к модели; одно и то же предчувствие не чаще раза в двое суток. Можно ответить «Спасибо», «Не сейчас» или «Не замечать такое».
- **Варианты будущего.** Когда вы просите совета («стоит ли…», «что лучше…», «как быть…»), она сначала прогоняет 2–3 варианта развития «умной» моделью и показывает под ответом, чем каждый, вероятно, кончится. Один дополнительный запрос, в пределах дневного лимита.
- **Собственный характер.** Её вкусы, привычки и причуды, отдельные от ваших, понемногу растут в фоне: не больше одного нового пункта каждого вида за раз, сила от 0 до 5 (0 — переросла).
- **Личная философия.** Со временем она формулирует до девяти принципов. Принцип принимается только если вырос из её реального опыта (уроков, моментов, мнений, дневника), и у каждого видно, откуда он взялся.
- **Самописные навыки.** Заметив повторяющиеся просьбы, она пишет себе навык: текстовую инструкцию, шаги и слова-триггеры. Навык не может запускать программы, читать файлы или ходить в сеть; подозрительные навыки отбрасываются. До одобрения навык не работает, но его можно проверить в песочнице (без памяти о вас). Одобренный навык включается по триггеру или команде `/имя`.
- **Самоулучшение.** В фоне она перечитывает свои ответы, ставит им оценки 1–10 и предлагает до двух правок души: урок общения, правило стиля, новое описание себя или сдвиг черты (не больше ±5). Ничего не меняется без вашего «Применить».

Фоновые задачи глубины идут через общий планировщик, только когда вас нет рядом не меньше 20 минут, «умной» моделью и в общем дневном лимите запросов. Частота зависит от уровня активности фонового обучения; каждую способность можно выключить в «Настройках глубины».


## Архитектура 2026: фоновые AI-задачи, модульный интерфейс и происхождение памяти

### Длительные запросы без блокировки HTTP (этап 3)

`launcher/yaeri-background.ps1` запускает отдельный **Windows PowerShell 5.1** процесс (`launcher/yaeri-background-worker.ps1`) для фоновых размышлений и длительных API-вызовов: чат, эмбеддинги, индексация, самопроверка, генерация планов и задачи развития. Пока выполняется Cloud.ru, основной сервер продолжает обслуживать сайт, запросы состояния и управление памятью.

Для длительных API-запросов сервер отвечает `{ "pending": true, "jobId": "…" }`. Клиент самостоятельно проверяет `GET /api/jobs/<id>` и прозрачно получает исходный ответ после завершения. Одновременно выполняется **одна** длительная AI-задача; приоритет пользовательского запроса выше фоновой работы. При запуске нового диалога ещё не завершённая фоновая задача отменяется. Короткие действия продолжают работать непосредственно в основном сервере.

**Безопасность состояния:** рабочий процесс получает только *копию* файлов `data/*.json` в отдельном каталоге `data/.bg-work-*/snapshot`. Он никогда не записывает основную базу напрямую. По завершении основной сервер проверяет SHA-256 исходных версий **всех изменённых JSON-файлов**, прежде чем применить что-либо, и записывает файлы последовательно посредством временных файлов и `File.Replace`. При конфликте с более новым изменением пользователя результат отбрасывается; для пользовательского запроса предлагается повторить его. Это гарантирует отсутствие тихой перезаписи новых JSON-изменений фоновой копией, хотя **не является многодокументной ACID-транзакцией**: при системном сбое между записями разные JSON могут быть разных версий. На время работы отдельного PowerShell-процесса приложение не зависит от открытой вкладки, но основной сервер должен оставаться запущенным.

Ограничения: изменение API-ключа и некоторые короткие команды продолжают выполняться непосредственно в серверном потоке; одновременный запуск двух экземпляров `Yaeri.bat` из одной папки не поддерживается. Задачи не выполняются при выключенном компьютере.

### Интерфейс как независимые исходные модули (этап 5)

`site/index.html` содержит только HTML-разметку. Стили вынесены в `site/styles.css`; стартовые настройки — `site/js/prefs.js`, граф «Второго мозга» — `site/js/brain.js`. Остальная логика находится в отдельных исходных файлах `site/src/`: `settings.js`, `chat.js`, `rag.js`, `memory.js`, `avatar.js`, `soul.js`, `soul3.js`, `evolution.js`, `soul-visuals.js`, `understanding.js`, `depth.js`, `core.js`, `bootstrap.js`.

Исходные фрагменты специально объединяются в один `site/js/app.js` **без изменения порядка и области видимости**, чтобы не ломать старые зависимости замыканий. После любой правки в `site/src/` выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\build-site.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\build-site.ps1 -Check
```

Готовый `site/js/app.js` хранится в репозитории: конечному пользователю Node.js и сборка не нужны. Тест `tests/check-site.js` проверяет порядок скриптов, их синтаксис и точное соответствие исходникам.

### Источники и достоверность воспоминаний (этап 2)

`launcher/yaeri-provenance.ps1` задаёт единый формат `evidence` для новых фактов, событий, заметок, воспоминаний, планов и предположений. Он сохраняет `origin`, `sourceId`, `quote`, `confidence`, `status`, `recordedAt`. Виды происхождения: `user_quote` (пересказ слов пользователя, **не независимая проверка**), `user_manual` (внесено хозяином), `assistant_hypothesis` (догадка), `assistant_generated` (генерация модели), `creative` (художественное), `conversation` (сырые реплики), `document` (источник из RAG), `legacy_unverified` (старые записи без понятного источника).

Метаданные сохраняются в существующих JSON-файлах, поэтому отдельная миграция не нужна; старые записи сохраняют работоспособность, но не считаются автоматически подтверждёнными. В контексте RAG и рабочей памяти явно обозначаются неподтверждённые сведения. Новые endpoints: `GET /api/evidence` для сводки источников; раздел «Душа → Soul 3.0 → Происхождение памяти» показывает типы записей. Цитата подтверждает происхождение фразы, а не истину самой фразы.

Контрольные команды: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test-background.ps1` и `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test-provenance.ps1`. GitHub Actions выполняет их на Windows вместе с прежними проверками.

## Автоматическое обновление Yaeri при запуске

Начиная с этого обновления `Yaeri.bat` **автоматически проверяет актуальный `main` перед запуском сервера**. Если приложение находится в обычном Git-клоне репозитория `Aspksa/Yaeri`, Git доступен, интернет работает, выбрана ветка `main` и в отслеживаемых файлах нет локальных правок, обновление применяется через **fast-forward only**. Хозяину больше не нужно вводить `git pull origin main` перед каждым запуском.

Скрипт `launcher/yaeri-update.ps1` допускает только доверенный `origin` на GitHub `Aspksa/Yaeri`. Он никогда не вызывает `git reset --hard`, не удаляет локальные файлы, не пытается автоматически объединять расходящиеся истории и не перезаписывает отслеживаемые правки. Если Git отсутствует, приложение открыто из ZIP, нет сети, переключена другая ветка или обнаружены изменения, автообновление **пропускается**, а уже установленная Яэри запускается как обычно. Время ожидания загрузки из GitHub ограничено 25 секундами.

**Личные данные и ключ:** папка `data/` и файл `config/yaeri.config.json` остаются в `.gitignore` и не отправляются на GitHub. Их обновление не затрагивает. Если локально изменён файл, который Git отслеживает, автообновление пропускается, вместо перезаписи. Обновления запускаемого кода загружаются из основного репозитория, поэтому он должен оставаться доверенным.

**Первое обновление:** старая версия `Yaeri.bat` ещё не содержит вызова автообновления. Для его установки нужно один раз обновить Git-клон вручную (`git pull --ff-only origin main`) либо заново клонировать репозиторий. После этого при следующих запусках `Yaeri.bat` обновления будут проверяться автоматически. Для ZIP-копий без папки `.git` автоматическая установка недоступна.

Проверка безопасности: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test-autoupdate.ps1`.

## Vector 2.0 — гибридная, личная и доказательная память

Модуль `launcher/yaeri-vector.ps1` объединяет **семантическую близость эмбеддингов Cloud.ru и точный BM25**, а `launcher/yaeri-vector-index.ps1` отвечает за инкрементальную индексацию и качество памяти. Установка отдельной базы данных, Python или Node.js не нужна. Новая система включена по умолчанию; её можно отключить в «Душа → Soul 3.0 → Vector 2.0», вернув прежний поиск.

Возможности всех 15 направлений развития:

1. **Hybrid BM25 + embedding:** при поиске учитываются и вектора, и совпадения имён, названий и терминов. Когда эмбеддинги недоступны, точный поиск остаётся работоспособным.
2. **Reranker:** локальное повторное ранжирование, **не отдельный дорогостоящий нейросетевой reranker**. Учитываются семантика, BM25, свежесть, важность, источник и оценки хозяина.
3. **Эмоциональные связи:** только явно процитированные слова хозяина («рад», «устал», «грустно» и т. д.) могут помечать контекст как эмоциональный; это **не** диагноз или утверждение об истинных эмоциях.
4. **Время:** у новых фрагментов документов сохраняется дата; старые записи получают меньший бонус свежести, но не удаляются. История разговора не подсовывается повторно в качестве воспоминаний текущего окна.
5. **Ассоциации:** граф Soul Evolution используется для связи воспоминаний.
6. **Память отношений:** значимые события и предпочтения хозяина участвуют в общем поиске и учитываются при ранжировании.
7. **Пространства памяти:** документы, разговоры, факты, эпизоды, дневник души, привязанность, предпочтения, исправления, карта хозяина и заметки остаются разными коллекциями.
8. **Контекстное ранжирование:** истина и предположение не равны; записи с известными источниками получают понятную атрибуцию. Близость по смыслу не является доказательством истинности.
9. **Недеструктивная консолидация:** одинаковые записи не повторяются в одном коротком контексте; отчёт качества показывает дубли и семантически похожие пары для проверки без удаления оригиналов.
10. **Противоречия:** конфликтующие версии фактов и ранее зарегистрированные конфликты показываются как требующие уточнения, не разрешаются автоматически.
11. **Два шага по графу:** связанным фактам и эпизодам может быть назначен небольшой дополнительный вес; связь не является доказательством причинности.
12. **Предпочтения хозяина:** подтверждённая карта и стиль общения участвуют в отборе с уважением к существующим настройкам приватности.
13. **Инкрементальные эмбеддинги:** переиндексация сохраняет вектора неизменившихся записей и пересчитывает только изменённые фрагменты. Точные дубликаты чанков переиспользуют уже существующие вектора.
14. **Обратная связь:** явные оценки ответа (+1/−1) корректируют вес участвовавших источников в узких пределах; плохой ответ не приравнивается к ложному факту. Повторное изменение одной оценки заменяет предыдущее.
15. **Карта качества:** `GET /api/vector` возвращает число записей по коллекциям, число векторов и лексических записей, дубли, кандидатов на семантическое объединение, нерешённые противоречия и статистику экономии эмбеддингов.

Маршруты API: `GET /api/vector`, `POST /api/vector/search`, `POST /api/vector/settings`. Поиск через Cloud.ru выполняется в существующем асинхронном PowerShell-воркере и не блокирует HTTP-сервер. В разделе «Душа → Soul 3.0» можно настроить ранжирование и ассоциации, найти воспоминание и посмотреть качество. Тексты поисковых запросов не сохраняются в отдельной телеметрии Vector 2.0: записываются только счётчик и время последнего поиска.

Данные `data/vector-v2.json` автоматически создаются локально и игнорируются Git; личные файлы предыдущих версий не мигрируют и не удаляются. Переиндексация `POST /api/reindex` при неизменившейся модели экономит токены эмбеддингов. При смене модели старые вектора для неё не переиспользуются.

**Тест:** `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test-vector2.ps1`. На Windows CI проверяются гибридный поиск, отдельные коллекции, ассоциативные связи, контроль повторов, конфликты, объяснимые эмоции, обратная связь, сохранение настроек и работа инкрементального индекса без реального ключа Cloud.ru.

Ограничения: алгоритм использует существующие embeddings, а не обучает embedding-модель. Для высоконагруженных коллекций потребуется отдельная индексная структура, а для независимой проверки фактов — внешний источник; Vector 2.0 не выдаёт догадки за проверенные знания.

## Yaeri Life 4.0 — модель мира, качество разума, нежность, инструменты и офлайн

Дополнения реализованы без обязательных внешних программ. В новых модулях `launcher/yaeri-life.ps1` и `launcher/yaeri-local.ps1`:

Сохраняет происхождение сведений и различает ассоциацию и *заявленную* причину; автоматически не выдаёт корреляцию за установленную причинность.
- **№5. Самооценка качества:** отдельно показывает оценки полезности ответов хозяином и проверенные исходы ранее созданных прогнозов. Хозяин отмечает, сбылся ли прогноз; самопроверка AI не используется как объективное подтверждение.
- **№9. Личный язык нежности:** четыре режима (мягкий, игривый, практичный, сдержанный) и необязательное одобренное хозяином обращение; действуют прежние границы дружеского/романтического стиля Soul 3.0. Настройки не разрешают навязчивость или имитацию человеческих чувств как фактов.

Каждое предложение изначально `proposed`, требует явно нажать «Одобрить», после чего хозяин может запустить или отключить его. Нет выполнения произвольных программ, shell-команд, внешних URL или записи файлов.

Без установки программ доступен детерминированный диалог с поиском по сохранённой локальной памяти, планам и заметкам. Это **не полноценная генеративная языковая модель**, и такой режим честно сообщает о своих ограничениях. Все данные сохраняются в `data/`.

### Полноценная офлайн-генерация без Ollama (необязательно)

Для генеративного общения можно самостоятельно запустить совместимый локальный сервер **llama.cpp** с загруженной GGUF-моделью. Яэри не скачивает бинарные файлы или веса и не отправляет пользовательские сообщения в интернет. Официальная документация: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md

1. Самостоятельно установите `llama-server.exe` из официального проекта и скачайте совместимый GGUF-файл модели, подходящий по памяти компьютера.
2. Поместите GGUF-файл, например, в `models\yaeri.gguf` (эта папка игнорируется Git).
3. Запустите сервер **только на loopback**, из папки проекта (укажите настоящий путь до вашего исполняемого файла):

```powershell
& "C:\Путь\к\llama-server.exe" -m ".\models\yaeri.gguf" --host 127.0.0.1 --port 9931 -a yaeri-local
```

4. В Яэри откройте **«Душа → Soul 3.0 → Автономность без облака»**, включите режим и нажмите «Проверить локальную модель». Если облачного ключа нет, включить автономность можно в **«Настройки → Подключение → Запустить без Cloud.ru»**.

При работающем `llama.cpp` отправка чата идёт исключительно на `http://127.0.0.1:9931/v1/chat/completions`. Проверка доступности идёт на `http://127.0.0.1:9931/health`. Адрес жёстко ограничен loopback, HTTP-перенаправления и прокси запрещены. При выключенном локальном сервере Яэри возвращается к встроенной памяти, **не к Cloud.ru**. При смене на обычный режим Cloud.ru вновь разрешается, если API-ключ настроен.

**Ограничения:** качество локальной генерации зависит от отдельной GGUF-модели и характеристик компьютера. Встроенный поиск без модели не умеет придумывать длинные оригинальные ответы, обрабатывать произвольные сложные вопросы и самостоятельно проводить многошаговые исследования. Векторизация новых фраз в офлайн-режиме Cloud.ru недоступна; работает BM25 и ранее сохранённые векторы там, где они применимы.

API: `GET /api/life`, `POST /api/life/settings`, `POST /api/life/local/test`, `POST /api/life/forecast`, `POST /api/life/tools/propose`, `POST /api/life/tools/decide`, `POST /api/life/tools/run`. Настройки хранятся в `data/life-4.json`, который не попадает в Git. Старые файлы памяти не изменяются обязательной миграцией.

Windows PowerShell 5.1 smoke: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test-life4.ps1`.

## Evolution 5.0 — учиться думать лучше (16 направлений)

Система `launcher/yaeri-evolution5.ps1` и `launcher/yaeri-evolution5-eval.ps1` дополняет Soul, Depth, Life 4.0 и Vector 2.0, не переобучая базовую языковую модель и не заменяя существующую память. Данные сохраняются локально в `data/evolution5.json` с атомарной записью; старые JSON не изменяются обязательной миграцией.

Выбранные возможности: **№9** учится выбирать методы с проверенными исходами (минимум три независимые оценки); **№10** строит причинные гипотезы с источниками и альтернативными объяснениями; **№11** моделирует мысленные эксперименты с проверяемым прогнозом и критерием; **№12** предлагает новые концепции из минимум двух разрешённых источников памяти, принятие вручную; **№13** обнаруживает пробелы карты понимания и конфликты фактов; **№14** ведёт многодневные учебные цели со следующим шагом и журналом фактически выполненных действий; **№16** предлагает перенос одобренных методов в другие области с отдельной проверкой; **№25** выбирает возможные долгосрочные цели из пробелов и не активирует их без согласия хозяина; **№26** сравнивает цели по важности, срочности и сложности; **№33** использует ограниченный детерминированный набор тестов покрытия инструкций для новых методов; **№34** предлагает безопасные методы мышления из предопределённого списка; **№35** запоминает категории ошибок на основе оценок хозяина; **№36** выбирает быстрый, глубокий или осторожный ответ по сложности запроса; **№37** считает Brier score по вручную проверенным прогнозам; **№38** автоматически откатывает одобренные стратегии при выраженном ухудшении оценок с достаточной выборкой; **№40** объединяет цели, пробелы и проверки в дневной цикл.

В интерфейсе «**Душа → Глубина → Evolution 5.0**» можно задать учебные цели, одобрить предложенные, добавить исследовательский вопрос, записать причинную гипотезу и её проверку, запустить исследование, посмотреть новые концепции, предложить метод и увидеть результат безопасного теста, вручную одобрить или отключить, оценить вероятность прогнозов, перенести подход в другую область и посмотреть дневник ошибок и откатов. Программа не запускает произвольный код, не меняет веса модели и не считает свои гипотезы доказанными фактами.

**Обычная работа не вызывает дополнительных платных AI-запросов.** Кнопка «Проверить развитие сейчас» выполняет локальный цикл с ограничением раз в сутки для автоматического режима. По желанию можно разрешить автоматический дневной обзор (изначально выключен); он выполняется фоновым изолированным процессом, пока сервер работает. Только явное нажатие «Исследовать с AI (1 запрос)» при выбранной *одобренной* цели, с минимум двумя разрешёнными подтверждёнными источниками, обращается к текущей облачной модели и учитывает дневной лимит. В офлайн-режиме платное модельное исследование недоступно, локальные проверки и журнал работают без облака.

**Особое ограничение оценки:** тесты методов проверяют только наличие нужных инструкций, не реальное качество ответа. Оценки хозяина и Brier score дают независимые наблюдения, но из-за небольших выборок и изменяющихся вопросов сравнение «до/после» не доказывает причинное влияние стратегии. Поэтому автоматический откат консервативен и меняет только активность правила, а не файлы или личность Яэри.

API: `GET /api/evolution5`, `POST /api/evolution5/settings`, `/cycle`, `/gap`, `/hypothesis`, `/experiment`, `/experiment/review`, `/concept`, `/concept/decide`, `/goal`, `/goal/step`, `/strategy`, `/strategy/decide`, `/calibration`, `/calibration/review`, `/transfer`, `/transfer/decide` и `/research` (все POST без метода GET). Исследование работает через уже существующий асинхронный воркер, не задерживая HTTP-сервер.

Тест Windows PowerShell 5.1: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test-evolution5.ps1`. Проверяются источники, предложения, эксперимент, синтез, цели, выбор метода, контроль ухудшения, калибровка, локальный цикл, имитированный один AI-запрос и повторное чтение JSON.
